05 · Integration
Today: nowhere · Tomorrow: three bridges

Where the two systems meet

OGRO · PostgreSQL
NestJS API + React panel. Owns field truth: applications, inputs, visits, collections, settlements.
NO API
NO WEBHOOK
WEGRO-INVESTOR · MySQL
Laravel + Bagisto. Owns capital truth: investors, products, returns, agents, payouts.
Three bridges if the roadmap needs them
01
Settlement → payout
OGRO settlement/deposit events push to Investor as signed events, so investor payouts reflect what actually settled in the field.
02
Impact stats
One read-only internal endpoint on OGRO feeds Polygon\Wegro\Stats — real numbers instead of seeded aggregates.
03
Keep identity apart
Farmers/field officers and investors/agents are different populations; SSO is not warranted by the role models.
Contract rules: HMAC-signed payloads · idempotency keys · retry with backoff · source-system event IDs · never a shared database.

Deployment & infrastructure

OGRO backend
  • Dockerfile → image wcp-backend
  • compose service wcp-backend, restart always
  • APP_URL https://api.dev.wegro.global/api
  • Postgres 18.142.55.212:5432 · db wcp-backend
  • SendGrid SMTP for mail
OGRO frontend
  • Vite build → nginx container
  • client https://dev.wegro.global
  • PWA enabled, installable
  • Local DB via postgres-docker compose
WEGRO-INVESTOR
  • docker/Dockerfile.production
  • fpm + nginx + supervisor + laravel-cron
  • entrypoint.sh boot sequence
  • php artisan storage:link + perms on deploy
  • Horizon worker on Redis
Shared infra
  • wegro-docker compose: proxy-server + varnish
  • redis + sentinel (queues, cache)
  • mysql for Bagisto
  • Never deploy the two systems from one pipeline
  • Known gap: no CI/CD yet · migrations by hand
