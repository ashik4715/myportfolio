The Loan Lifecycle — ProjectApplication, the core state machine

01
ApplyFarmer submits to a project: land, survey answers, credit score
02
ApproveField officer recommends, supervisor checks; reject / blacklist paths
03
AgreementLoan agreement drafted, approved, stored; corrections tracked
04
DisburseBank account opened, CRM approval, funds move to farmer
05
InputsInput bundle selected, acknowledged, distributed to farmer
06
VisitsIdentity + crop-health ×3 + harvest — each a completed checkpoint
07
CollectCollections & deposits recorded; late fees and penalties applied
08
SettleSettlement run to partner bank; full audit log kept
Dual sign-off

Every project needs COO approval, then CFO approval before any money moves — nobody moves large money alone.

Everything is logged

ProjectApplicationLog plus corrections on agreements, collections and deposits — ready for a bank audit at any time.

Bank-side board

/bank-panel runs the whole borrower pipeline in bulk — 11 bulk PATCH actions + tracking sheet.

WEGRO — Two System Architecture (17-slide deck)

## Slide 1 — Title
# WEGRO — Two System Architecture
One platform. Two systems.
- System 1 — OGRO: ERP for Farmers & Field Officers (NestJS + React)
- System 2 — Wegro-Investor: Investor Backend & APP (Laravel + Bagisto)

## Slide 2 — The Big Picture
- OGRO runs the field: farmers, field officers, drone & input ops, partner banks — NestJS API (PostgreSQL) + React 18 PWA — 3,454 files, 347 API endpoints, 85 entities
- Wegro-Investor runs the capital: investors, agents, zones, payouts — Laravel 8 + Bagisto (MySQL + Redis) — admin dashboard + mobile APP — 14 custom packages, 170 route entries
- Bridge: field settlements ↔ investor payouts; aggregate impact stats to the APP (no shared DB)

## Slide 3 — OGRO domain
Farmer registry (credit score, OTP/call verification, lands, surveys) · Loan programs (project applications → agreements → disbursement; COO+CFO dual approval) · Input distribution (products, bundles, warehouses, dealers, vendors, POs, transfers, sales) · Field execution (officers, notices, 5-stage visits) · Money flow (collections, deposits, settlements, penalties) · Website CMS.

## Slide 4 — OGRO stack
Backend: NestJS 10, REST /api + Swagger /docs, TypeORM + PostgreSQL (68 migrations), JWT 1d/refresh 7d, bcrypt, role-permission RBAC + guards, Socket.IO, Firebase FCM, AWS S3, SendGrid, cron, throttler.
Frontend: React 18 + Vite, Redux Toolkit + RTK Query, React Router 6 with guards, Tailwind + rsuite, ApexCharts/Google Charts/Maps, PWA, one RTK slice per backend module (create-api.sh).

## Slide 5 — Backend module map
~36 modules, 85 entities: people (auth/users/roles/permissions/otp/field-officers/farmers/region/user-locations), loan core (projects/project-applications/loan-agreements/visits/collections/deposits/settlements/banks/call-dispatch), inventory & trade, field content (surveys/questions/sections/answers/notices), platform (websocket/firebase/notifications/email/file-upload/export/activity-log/system-settings), website CMS.

## Slide 6 — Loan lifecycle (deck2 design)
8-step state machine: 01 Apply (land, survey, credit score) → 02 Approve (officer recommends, supervisor checks; reject/blacklist) → 03 Agreement (drafted, approved, corrections) → 04 Disburse (bank account, CRM approval) → 05 Inputs (bundle selected, acknowledged, distributed) → 06 Visits (identity + crop-health ×3 + harvest) → 07 Collect (collections, deposits, late fees, penalties) → 08 Settle (bank settlement + audit log).
Bottom cards: dual sign-off COO→CFO · everything logged · /bank-panel runs the pipeline with 11 bulk PATCH actions.

## Slide 7 — Frontend architecture
Structure: routing/ (AllRoutes, AppRoutes, guards), store/ (app, auth, filters + features//Api), modules/ (35), components/ (MasterLayout, ProtectedRoute, PDF), configs/permissionsEnum, enums/AppEnums.
Rules: RTK Query only; screens gated by PermissionsEnum mirroring backend; main/report/AI API URLs. Signature screens: BankTrackingSheet, BankPanel, InputPanel, ProjectGanttChart, DisbursementPendingApprovals, EBLBankPdfGenerator.

## Slide 8 — API surface
60 controllers, 347 endpoints: auth (/auth/login, refresh), farmers (+credit-score, phone update approvals), applications (disburse-loan, approve, blacklist, late-fee), bank flow (11 bulk actions), visits (mark-as-completed ×5), collections (onboarding fee, correct, approve), inventory (PO receive, transfers, sales payments), platform (notifications, firebase push, activity logs). Live docs at /docs.

## Slide 9 — Investor domain
Investor APP: OTP login → products → invest → track returns → FCM push → Aamarpay pay in/out.
Admin: onboarding review, products & returns, agent hierarchy (Zone→Territory→Agent→Zonal Manager), reports (sales/customers/projects/refunds/transactions/taxes).
KPIs: 14 custom packages · 24 Bagisto packages · 170 routes · 3 surfaces.

## Slide 10 — Investor architecture
Flow: Investor APP → api routes (Polygon + Webkul API) → services (OnboardingService, repositories, listeners) → Eloquent (proxy pattern) → MySQL + Redis/Horizon.
Key: Polygon\Notification\PolygonFcmChannel (push), Polygon\Aamarpay (payments), Polygon\Wegro (glue + Stats DTO).

## Slide 11 — The investor loop (NEW)
01 Onboard (application → ops review) → 02 Products (browse investment products & projects) → 03 Cart → 04 Order → 05 Pay (transaction via Aamarpay + IPN webhook) → 06 Return (disbursement to investor) → 07 Reinvest (returns into new products).
Certificates: yearly tax certificate per fiscal year; order certificate signed by the CEO — both downloadable in-app, generated from real order/return history.
Automation: every step emits a domain event → Laravel queues (Horizon) + cron jobs send automatic emails (payment receipts, order confirmations, return notices, certificate delivery); new product published → FCM push to investor apps.

## Slide 12 — Custom packages
Agent (accounts, OTP+JWT) · Application (onboarding) · InvestmentProduct · InvestmentReturn · Report · Zone/Territory · Notification (FCM) · Aamarpay · OTP/Faq/CacheControl/Wegro.

## Slide 13 — Investor API
APP API: POST /api/shoot-otp, /validate-otp, /agent/login, /token/refresh, password/change; GET /agent/me, /agent/manager.
Payments: /aamarpay/success|cancel|fail|ipn (verify signatures).
Admin: application (+datatable, approve, resubmit), investmentproduct, sales/returns, report/*, agents, faqs. Shop: application, investmentproduct, investmentreturn, faq, report. Storefront: 105 Bagisto API endpoints.

## Slide 14 — Relationship
Independent stacks today (languages/DBs/pipelines separate). Recommended: settlement/deposit events → payouts (HMAC webhook); GET /impact-stats on OGRO feeds Wegro\Stats; payout confirmations back to OGRO.

## Slide 15 — Deployment
Ogro: wcp-backend Docker, staging api.dev.wegro.global, Postgres, S3, SendGrid, nginx frontend, shared wegro-docker infra.
Investor: Dockerfile.production (fpm/nginx/supervisor/cron), MySQL, Redis+Horizon, storage:link post-deploy.
Alert: secrets in staging compose must be rotated.
