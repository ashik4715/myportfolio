03 · Safety
Four doors before any data is touched

SAFE BY DESIGN, NOT BY LUCK

Door 1
Are you logged in?

No pass, no access. The pass expires after one day.

Door 2
Is this screen allowed?

Every screen has its own permission. A farmer's record is not for everyone.

Door 3
What is your role?

An officer sees his own farmers, a manager his region, head office everything.

Door 4
Is the data real?

A wrong date or an impossible number is refused, with a clear message.

And after the doors
  • Every change is recorded — who changed what, and when. That is what makes a bank comfortable.
  • After every release, we print the full list of open doors and check that nothing private became public.

THE INVESTOR PLATFORM

For the investor — a mobile app
  • Logs in with a code on the phone — no password to remember
  • Browses products, invests, follows returns and refunds
  • Pays in and out through a local payment gateway
  • Gets a phone notification when something happens
For the business — an admin dashboard
  • Reviews each new investor: approve, or ask for a re-submit
  • Creates products, runs the returns, downloads reports
  • Follows the agent network: area → territory → agent → manager
  • Keeps every document and payment in one place

06 · Go live
Two pipelines, one shared infrastructure

HOW IT GOES LIVE

The farm system
  • Two containers: one for the engine, one for the screens
  • Both restart by themselves if they crash
  • Same behaviour on a laptop and on the real server
The investor system
  • One bigger container with the web server
  • Background workers send emails and run return payments
  • Scheduled jobs do the routine work
The shared base
  • A proxy, a cache, a message queue, and the databases
  • Both systems use it, and both are released separately
  • One problem never takes down the other product
One honest gap
  • No fully automatic release process yet
  • Database changes are applied by hand
  • The next fix: about two weeks of work
